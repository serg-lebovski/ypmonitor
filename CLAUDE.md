# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

YPMonitor — система мониторинга резервного копирования: Windows-агент наблюдает за папками бэкапов
и журналом событий, Docker/Linux-сервер принимает отчёты, показывает дашборд и рассылает отчёты/тревоги
в Telegram и на почту. Полное описание функциональности — в [README.md](README.md); здесь — то, что нужно
знать при изменении кода и не видно из отдельных файлов.

## Сборка и запуск

```bash
# Локальная сборка отдельного проекта (нужен .NET 8 SDK)
dotnet build src/Ypmon.Server/Ypmon.Server.csproj
dotnet build src/Ypmon.Agent/Ypmon.Agent.csproj

# Запуск сервера локально (SQLite создаётся в src/Ypmon.Server/data/ypmon.db)
cd src/Ypmon.Server && dotnet run --no-launch-profile   # веб :8080, приём отчётов :8081

# Установщики (single-file, self-contained) — PowerShell, нужен Inno Setup для агента
pwsh build/build-all.ps1                     # всё (windows-server, windows-agent, linux-server)
pwsh build/build-all.ps1 -Target agent-win   # только агент

# Выкатка агента на прод (собирает установщик, кладёт в том agent-updates, сверяет SHA256)
$env:YPMON_SSH_PW = 'пароль'; pwsh build/release-agent.ps1     # прод-хост зашит в параметрах скрипта
```

Автотестов в репозитории нет. Проверка изменений — прогон локального сервера и, для агентских замеров
(WMI/журнал событий), запуск на реальной Windows.

## Архитектура: три проекта, один контракт

- **Ypmon.Shared** — DTO, которыми обмениваются агент и сервер ([Contracts.cs](src/Ypmon.Shared/Contracts.cs)).
  Это единственная связь между ними; менять его нужно с оглядкой на совместимость (см. ниже).
- **Ypmon.Server** — ASP.NET Core Razor Pages (UI) + minimal-API эндпоинты (`/api/*`) в
  [Program.cs](src/Ypmon.Server/Program.cs). Вся логика — в `Services/`.
- **Ypmon.Agent** — один self-contained `.exe`, работающий в двух режимах из одного бинарника:
  двойной клик → окно WinForms; служба Windows `YpmonAgent` → тот же exe в фоне. Оба читают один
  `config.json`; системный мьютекс не даёт запуститься двум экземплярам одновременно.

Направление связи **строго одностороннее**: агент только шлёт исходящий `POST /api/report` с `X-Api-Key`.
Сервер не открывает соединений к агенту. «Команды» агенту (запросить отчёт, обновиться, перезагрузиться)
работают так: сервер кладёт номер команды в ответ на heartbeat, агент сам её вычитывает и исполняет
(`RemoteCommandService` на сервере, `RemoteCommandHandler` в агенте). Список команд закрыт и зашит в
агенте — с сервера приходит только номер, никаких строк для исполнения.

## Контракт совместимости агент↔сервер (критично)

Парк агентов обновляется постепенно и не одномоментно с сервером, поэтому:

- **DTO в Contracts.cs расширяются только аддитивно.** Новое поле — nullable или с дефолтом. Старый
  сервер молча проигнорирует незнакомое поле, старый агент его просто не пришлёт (в UI/отчёте будет
  прочерк). Никогда не переименовывать и не удалять поля, не менять их смысл.
- **Заморожены**: эндпоинты `POST /api/report`, `GET /api/ping`, `/api/agent/version`,
  `/api/agent/download` и формат plain-text `version.txt`.
- **Обновление агента — «храповик»**: агент скачивает новый exe по своему запросу, установщик тоже
  берётся с сервера каждый раз. Значит, правка в `installers/agent/*.iss` или в скриптах установки чинит
  уже развёрнутые СТАРЫЕ агенты, а изменение C#-кода агента вступает в силу только версией позже.
- При выпуске агента поднимайте `<Version>` в [Ypmon.Agent.csproj](src/Ypmon.Agent/Ypmon.Agent.csproj).

## Схема БД — без EF-миграций

Сервер работает и с PostgreSQL (прод), и с SQLite (локально). Провайдер выбирается в `appsettings.json`
(`Database:Provider`). Схема управляется вручную в [Program.cs](src/Ypmon.Server/Program.cs) при старте,
идемпотентно:

- новый столбец → добавить строку `ALTER TABLE … ADD COLUMN IF NOT EXISTS` (postgres) **и** параллельно
  `try { ADD COLUMN } catch { }` (sqlite) — это два отдельных блока в Program.cs, правьте оба;
- новая таблица → блок `CREATE TABLE IF NOT EXISTS` с обеими диалектными версиями;
- новую сущность так же регистрируют в [AppDbContext.cs](src/Ypmon.Server/Data/AppDbContext.cs).

**Ловушки SQLite (повторяющийся класс багов):**

- SQLite **не умеет `DateTimeOffset` в `ORDER BY` и в сравнениях**. Сортировать по `Id`
  (`OrderByDescending(x => x.Id)`) вместо `.At`/`.CreatedAt`; фоновую чистку по дате делать сырым SQL
  (`ExecuteSqlRawAsync`), а фильтрацию по периоду — в памяти после выборки. Забыв это, получишь 500 или
  молча несработавшую чистку.
- SQL `LIKE` **регистрозависим для кириллицы** (и в SQLite, и в Postgres): «ошибка» не найдёт «Ошибка».
  Текстовый поиск делать в памяти через `Contains(..., StringComparison.OrdinalIgnoreCase)` по свежему
  срезу записей, а не через `EF.Functions.Like`.

## Сервер: как принимается и оценивается отчёт

- [ReportIngestService.cs](src/Ypmon.Server/Services/ReportIngestService.cs) — точка входа отчёта.
  Heartbeat (раз в минуту) обновляет только время связи, диски, температуру; полный отчёт (раз в 6 ч)
  пишет всё и историю. **Оценку состояния делает сервер, не агент**: свежесть бэкапа по порогу в днях
  (глобальный / по серверу / по папке), офлайн по адаптивному порогу (2×heartbeat-интервал + запас),
  усадку бэкапа сравнением нового файла с предыдущим.
- [TelegramService.cs](src/Ypmon.Server/Services/TelegramService.cs) — клиент Bot API. Отправка идёт
  через пейсинг-гейт (лимит ~20 сообщений/мин в группу) и повторы при 429 и сетевых сбоях/таймаутах
  туннеля. Отчёт в группу — одно сообщение на клиента в его тему (forum topic).
- [TelegramReportService.cs](src/Ypmon.Server/Services/TelegramReportService.cs) — рассылка формируется
  по **единому снимку данных на момент старта** (`asOf`), потому что сама рассылка идёт минутами и без
  этого серверы в конце очереди ложно «уходят в офлайн» от хода часов. Одновременно идёт только одна
  рассылка; дата последней хранится в БД, чтобы рестарт в час отчёта не разослал дубль.
- Бот ходит в Telegram через SOCKS5 сайдкара AmneziaWG (обход DPI). Прокси-URL отдаёт
  `WireGuardProxyService`; см. раздел про AmneziaWG в README, включая требование `/dev/net/tun` на хосте.

## Инфраструктура

- `docker compose` поднимает три контейнера: `ypmon-postgres`, `ypmon-server`, `ypmon-awg` (сайдкар
  AmneziaWG). Секреты — только в `.env` и БД, в git не коммитятся.
- Самообновление сервера: git + хостовый воркер `ypmon-updater` через файловый канал в томе `./.update`.
  Кнопка в *Настройки → Обновление сервера* делает `git pull`, пересборку и перезапуск.
- Том `agent-updates` (`/app/agent-updates`) — сюда `release-agent.ps1` кладёт `Ypmon.Agent.exe` +
  `version.txt`; оттуда агенты автообновляются и скачивается установщик со страницы настроек.
- Шелл-скрипты и `deploy/ypmon-updater.service` должны оставаться с LF (задано в `.gitattributes`) —
  иначе не запустятся на Linux.

## Язык и стиль

Проект русскоязычный: UI, комментарии, сообщения коммитов, тексты в боте — на русском. Новый код держите
в том же стиле и с той же плотностью комментариев, что и окружающий (комментарии объясняют «почему», а не
«что»). Пользовательские строки не должны терять кириллические символы.
